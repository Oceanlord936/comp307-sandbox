## Concepts worked through (asked / explained)
- `document.write` while loading inserts at the script's spot; after loading (click, timer, `onload`) it calls `document.open()` and wipes the page
- `alert` blocks the page (often before the heading is drawn); `console.log` never touches the page
- `type="text/css"` / `type="text/javascript"` optional in HTML5; `type="module"` is required for modules
- A script only sees HTML above it. `defer` runs an external script after all HTML is read. Modules are deferred automatically
- Modules need a server (Live Server / `python -m http.server`); `file://` gives a CORS error
- `export` / `import { a, b } from './x.js'`
- `const` reassign → `TypeError`; an error stops the rest of the script
- `innerHTML` is HTML (tags work); `textContent` is plain text
- `function` declarations are hoisted; `const f = () => {}` is not (ReferenceError if called first)
- No `return` → `undefined`; `f` without `()` prints the function source
- `var` is function-scoped, `let` block-scoped
- Doubles: `25.555555555555557`, `0.1 + 0.2`; `toFixed(2)` for display
- What matters is *when* `getElementById` runs, not where the script is: inside an `onclick` it runs after load
- `<input type="button" value="...">` vs `<button>...</button>`; `<input>` has no closing tag
- `visibility: hidden` keeps the space; `display: none` collapses it
