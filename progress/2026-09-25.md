## Concepts worked through
- Styling goes in CSS; `tabindex` / `role` / `on...` handlers are attributes on the element
- `onkeydown` fires for every key, only on the focused element; filter with `event.key` (`"Enter"`, `" "`)
- Without `tabindex`, a div can't get focus, so it never gets key events. Tab to focus before testing keys
- F12 Console shows the error that silently stops a script
- `addEventListener("click", f)`: event name without "on", function without `()`
- Several `addEventListener` calls on one element all run; `el.onclick = f2` replaces `f1`
- Event names are a fixed browser list; a typo like `"clic"` gives **no error** and simply never fires
- `f` passes the function; `f()` runs it at load and passes its return value (`undefined`), so the listener is empty
- Using a `function` declaration before it's defined works (hoisting)
- Event object: `e.type`, `e.target`, `e.button` (0 left, 1 middle, 2 right); use `mousedown`, since `click` is left only
- Right-click fires `mousedown` → `mouseup` → `contextmenu`; the menu is `contextmenu`'s default, so `preventDefault()` goes there
- `e` exists only inside the listener the browser calls
- ThinkPad middle key is TrackPoint scroll, not a middle click, so case 1 can't be tested on it
- Modifier keys are booleans on the click's own event object (`e.ctrlKey`, not `controlKey`); one event, not two
- `if / else if` shows only the first match; separate `if`s + `msg +=` show every held key
- `addEventListener("load", init)` only registers `init`; the browser calls it once the page has loaded. Defining a function never runs it
- Direct `getElementById` in `<head>` → `null` (element not parsed yet) → TypeError, which stops the rest of that script
- `<body onload>` = `window.onload`: one slot, last one set wins; `addEventListener` adds to a list
- `el.focus()` = method (make focus happen); `addEventListener("focus", f)` = event (react to it)
- Inside an `addEventListener` callback, `this` is the element the listener is on
- CSS `background-color` → JS `backgroundColor`
- `blur` = losing focus; clicking a button already blurs the input, so `.blur()` is only needed when focus wouldn't move by itself
- `style.border = ""` removes the inline style
- Misspelled *variable* → ReferenceError (loud); misspelled *property* set → silent
- `setTimeout(f, ms)` schedules once and doesn't pause: log order is A, C, then B 3 s later. `f()` runs it now and schedules `undefined`
- `setInterval` repeats and returns an ID; save it at script level so Start and Stop both see it
- Starting twice overwrites the ID, so the first timer can never be cleared. Guard with `if (!timerid)` and reset to `null` in Stop
- `<select>`: `.value` = chosen option's `value` (falls back to its text if no `value` attribute); `.selectedIndex`; `.options[i].text` (or `sel[i].text`)
- `change` fires only when the choice actually differs; re-picking the same option fires nothing
- `form.elements[i]` loops every field; `.type` decides what to read: checkbox → `.checked` (true/false), others → `.value`
- Checkbox `.value` is the text sent on submit (default `"on"`), never the ticked state
- `<button>` in a form defaults to `type="submit"` (reloads page); use `type="button"`
